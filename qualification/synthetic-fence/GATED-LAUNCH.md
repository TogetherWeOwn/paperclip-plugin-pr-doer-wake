# Narrow gated launch component

This isolated, unintegrated component implements only the gated-fork portion of the selected supervisor design. It does not authorize protected execution or change the existing unconditional refusal. A successful return means only that the stub was released; it is not evidence of exec, runtime readiness, worker GO, successful phase completion or cleanup.

## Contract and assumptions

The caller is the trusted, single-threaded PID 1 of a fresh outer PID namespace, with SIGCHLD blocked before entry, no auto-reaping, and exactly one waiter. It establishes signal handling and exclusively owns the namespace and the cgroup-v2 phase subtree; other privileged actors cannot migrate the child or replace/mutate cgroup state. It opens the exact `phase/cli` cgroup directory, separately establishes its identity and placement below the exclusive parent, and records that identity and launch intent before calling. The code checks cgroup-v2 filesystem type, not cgroup identity, ancestry, leaf status, mount/proc namespace equivalence or exclusive control. `cgroup.procs` is opened separately for writing and reading; the complete bounded read independently observes the still-owned child's exact PID after the write. No arbitrary caller-provided process list is accepted as membership evidence.

The caller supplies an already verified, immutable, native executable through a CLOEXEC fd (not a script), trusted validated argv/environment and a synchronous `record_child` callback. This callback must durably record the child PID, pidfd association and phase identity before returning success; it must not reap, fork, block indefinitely, or release admission. The supervisor owns the result record immediately on fork. A pidfd is mandatory; there is no unsupported-kernel fallback. The child cannot fork or exec before its single-byte gate, and EOF or a bad token exits. Its own peer socket is closed, so supervisor death closes the gate. The stub closes all descriptors except gate and executable using `close_range`, clears the signal mask and resets SIGCHLD before exec; its other inherited ignored signal dispositions must be appropriate. It passes no stdio or RPC descriptors. Consequently this component alone cannot run the specified runtime protocol; a carefully reviewed descriptor allowlist/transport must be added before integration. Exec failure exits 127 and must be observed by the supervisor; no exec-status protocol is implemented.

Failures poison the result, close the gate and attempt SIGKILL plus bounded `waitpid` of the known unreaped child, including before cgroup enrollment. A record with a positive PID and `reaped == 0` remains owned and must be retained and handled by the sole reaper, even if the pidfd is absent; ECHILD is not treated as a successful receipt. The caller must permanently poison the case regardless of subsequent cleanup. On success it must retain the child and pidfd, collect its actual status and close the pidfd. The callback's record is not a substitute for a complete supervisor state machine.

The supplied deadline is absolute CLOCK_MONOTONIC. Checks surround launch steps, and cleanup polling stops at this deadline; system calls, scheduling and the callback cannot be physically bounded by it. A separate outer supervisor deadline is mandatory. The caller must also enforce the decision's separately recorded cleanup budget and treat blocking, deadline expiry, lost supervision and incomplete observation as unverified teardown. This component does not implement that outer deadline or provide a verified cleanup receipt.

## Explicit gaps and required evidence

Not implemented: namespace creation and procfs validation; runtime provenance/configuration and runc invocation policy; phase lock and safe resource allocation/removal; complete launch state machine and separate cleanup budget; continuous SIGCHLD handling and `waitpid(-1, __WALL)` drain; cgroup.kill and recursive populated=0; stdout/stderr/RPC descriptors and EOF handling; worker bridge, GO, response ACK/settlement; coordinator-loss handling; complete receipt and next-phase refusal enforcement. No claim is made about Actions kernel/cgroup capability or actual runtime security. The bounded membership read fails closed on overflow or malformed data, but tests do not demonstrate kernel cgroup semantics or concurrent migration resistance.

The decision requires a benign exact-head Actions capability fixture exercising the complete actual supervisor/runtime path and launch failure boundaries, independent Security acceptance before any protected execution, and Security then QA review. Until those and all other decision gates are met, preserve unconditional refusal. This code is not connected to the protected controller and must not be treated as a security boundary by itself.

`gated-launch-test.c` exercises only the pure membership parser and does not fork, access cgroups or execute a worker/controller. Compile with strict warnings and run it as an ordinary bounded unit test; it does not establish runtime capability.
