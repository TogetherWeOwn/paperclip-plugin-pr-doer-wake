# Synthetic phase-fence model (unfinished)

This is a disconnected in-memory model, **not** an executable isolation boundary, worker host, package transition test, or qualification evidence. It does not import, replace, or relax the retained scaffold's unconditional controller refusal. The scaffold is preserved separately and has not been extracted here. Never connect this model to package execution merely because its tests pass.

The coordinator owns a fresh identity token per phase, registers synthetic operations synchronously before handler dispatch, rejects overlapping or stale phases, and requires affirmative synthetic command/close-and-drain signals and settlement of registered operations. Failure, late dispatch, timeout, or ambiguity permanently poisons the sequence and prevents subsequent phase admission. If a false drain signal already allowed the next phase to start, a late dispatch poisons the sequence but cannot undo that admission or stop effects already running. This deliberately rejects incoming requests after finish starts, including ones that may have been valid in a real worker shutdown; it is conservative, not a complete SDK protocol adapter. Operation settlement here includes only what the caller places inside the operation promise; a future adapter must include response delivery and prove complete stream drainage, not assert them from process exit. Inputs are caller-provided promises, not independent attestations. Timeout/cancellation is never evidence of non-dispatch.

Before a protected run, independently review immutable trusted controller provenance, exact-head binding, runner/daemon exclusivity and isolation; satisfy the image-reference prerequisite and all Security → QA, Actions and release gates. Actual artifacts, host SDK/dependencies, worker RPC, state/journal fixtures, cross-version matrix, known-not-sent evidence, policy-negative behavior and real teardown remain unimplemented and unverified. No production credentials, host connection, installation or real effect is permitted.

The accompanying tests are proposed synthetic model tests only. The CI workflow includes them, but no Actions result is claimed until the exact head has run. Bounded pre-push checks apply before any push. The proposed [transition contract](TRANSITION-CONTRACT.md) describes outstanding fixture requirements, not implemented qualification.
