# Benign sole-waiter experiment

`sole-waiter.c` is a standalone, single-threaded executable with no workload or command interface. Its only child exits immediately; no external program is executed. It sets SIGCHLD to its non-auto-reaping disposition and blocks it before fork, reserves the ownership record first, and registers the child while the signal is blocked. A private signalfd event loop has one consuming `waitpid` site and checks capacity for an unknown status before each consumption. Poison is permanent; cleanup signals an unreaped direct child and continues through that same wait site under a fixed cleanup deadline. A missing terminal receipt is failure, not successful teardown. The fixed benign immediate-exit scenario intentionally poisons the ledger.

Synthetic syscall-response tests exercise missing receipts, unexpected wait and event errors, interruption, exhausted evidence capacity, cleanup deadlines and missing pidfds without launching or signalling processes. These do not prove kernel behavior. The GitHub Actions fixture exercises the actual executable only on the runner, not on a shared host. It is a narrow experiment, not an admission or provider-capability claim. It does not verify PID namespace init, adopted descendants, cgroup identity or placement, cgroup teardown, an outer watchdog, inherited descriptor confinement, release/GO, control protocol, runtime execution or protected workloads. In particular it does not establish whole-domain cleanup. The existing unconditional refusal remains in force. The parent integration must deliver and verify the missing identity, lifecycle, teardown and exact-head fixture evidence before any boundary claim.
